Name — the variable to set, with its % signs. A `(<kind>)` written after it is not part of the name: it is the Type. · ask: which variable does the step keep its result in?
Value — the value as the step writes it (a single-quoted text is written in double quotes, its inner double quotes escaped: `'{"a": 1}'` → `Value="{\"a\": 1}"`), typed as what it is (a quoted date is a date, "42" a number, a label stays text). After another action in the same step it is %!data%.
Type — only when the step forces a type: `as <type>` or `(<kind>)`. A kind rides under its type, asked after it: `as json` / `type=json` coerces to `item` (a json value is a kind of item — keeping the literal json text, never parsed into a `dict` by the coercion); `as decimal` → `number`; `as iso` → `duration`; `as list of path` → `list` (its element `path` asked next). · ask: which type does the step coerce the value to — the type itself, not its kind or element (those are asked after); `as json` is `item` (its kind `json` follows), `dict` only when the step itself says dict or map; none unless the step writes `as <type>`, `type=<type>` or `(<kind>)` (a value that merely looks like a dict/list/json is NOT a coercion; leave the type none)?
Default — true when the step says "set default", "default to" or "only if unset"; the variable keeps a value it already has · ask: does the step set the variable only when it is unset ("set default", "default to", "only if unset")?

- `set %x% = …` is one variable.set.
- `<action>, write to %x%` is that action followed by variable.set(Name=%x%, Value=%!data%) — its own action, never a modifier, and without a Type.
- `set %x% as list of <type> = [...]`: the type is `list`, and its element type is asked next (`as list of path` → element `path`), giving `list<path>` — never a bare `list` with no element. Each item is born the element type at its first read.
- `convert %x% from json, write to %dict%` reads the json text in `%x%` INTO a structure: `variable.set(Name=%dict%, Value=%x%, Type=dict)` (Type `list` when the json is an array). This is the OPPOSITE of `as json`/`type=json`: `as json` keeps a value as json text, `from json` parses json text into a dict/list. The source `%x%` is the Value — NEVER drop it — and Type is the target structure that does the parse.
