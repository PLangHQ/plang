Resume a snapshot value: the run goes on from where it stopped, in an app of its own, and the step answers what that run answers. A step phrased `resume %snapshot%` maps here. The `Snapshot` parameter is the snapshot value, usually a variable read back from where it was kept (`read file 'run.plang', write to %snap%`). Distinct from `goal.call`: it leads with the word `resume`, not `call`.

Only a snapshot the app itself signed, as it was saved, resumes. A snapshot with no signature (`SnapshotUnsigned`), one changed since it was signed (`SnapshotSignatureInvalid`) and one signed by an identity that is none of the app's own (`SnapshotNotTheApps`) are refused. A snapshot edited on purpose resumes once it is signed again: `sign %snap%, write to %snap%` is the signing module's step, not this one's.

A goal changed since the save is resumed at its saved place; when another action stands there, a warning says so and the run goes on. A place past the end of a goal or a step is refused (`StepNotFound`, `ActionNotFound`). `Parallel` (`don't wait`, `in the background`) runs the resumed run beside the step: the step gets a task at once.
