Take the run's state as it is now, as a snapshot value: the app and every part under it, the call stack included (each call where it stands, with its own variables). The app signs it with its own identity. A step that names the snapshot itself and no file (`save snapshot`, `take a snapshot`) maps here; saving a value to a file (`save %snapshot% to file 'run.plang'`) is file.save, and a snapshot is kept as a `.plang` file or a db row. Keeping the snapshot is the developer's own next step. A run resumed from it goes on from this step, so the save answers again, with a snapshot of the resumed run. Inside a task a save is refused (`SnapshotInTask`).
