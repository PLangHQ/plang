Take the run's state as it is now, as a snapshot value: its variables, its call stack (each frame where it stands, with its own variables) and what the app keeps. A step that names the snapshot itself and no file (`save snapshot`, `take a snapshot`) maps here; saving a value to a file (`save %snapshot% to 'run.snapshot'`) is file.save. Keeping the snapshot is the developer's own next step. A run resumed from it goes on from this step, so the save answers again, with a snapshot of the resumed run.
