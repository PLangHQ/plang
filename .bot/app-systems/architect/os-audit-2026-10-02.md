## 1. Security (fix first)

1. **A `write` grant also grants delete.** `terminal/code/Sandbox.cs:147`: `Writing = WriteFile | MakeDir | MakeReg | Truncate | Removing | …`, while `Of()` only authorizes `write`, so the app's own `delete` gate is bypassed. Fix: `Removing` only for `delete`.
2. **The sandbox follows symlinks when granting.** `Sandbox.cs:188` opens the granted path with `O_PATH` and no `O_NOFOLLOW`; `Authorize` approved the link's text while the kernel rule lands on its target. Fix: `O_NOFOLLOW`, or resolve then authorize.
3. **A sandboxed child inherits plang's whole environment** (secrets included: `OPENAI_API_KEY`, …). `terminal/code/Default.cs:339–343` adds to the inherited set and never clears it; `Sandbox.cs:20–21` hides `/proc` precisely to hide the environment. Fix: with `Permission` set, `Environment.Clear()` and pass only what the step and settings give.
4. **Elevation needs only `execute`** (UAC is the only guard), and elevated or attached mode silently ignores `Input`, `OnOutput`, `OnError`, `Environment` (`Default.cs:37–40, 60–79`). Fix: its own verb or ask; refuse ignored parameters.
5. **The archive `..` hole** in the os bot's draft unpack (an entry named `..` deletes the folder above); fixed in the archive module (43add1730), which replaces the draft.

## 2. Hand-built JSON: events and values must be types that write themselves

Every event between the screen, browser, terminal and plang is a JSON string or a `JsonObject`, re-parsed up to three times, and a goal sees text on Windows and a dict on Linux (`screen/code/Default.cs:35` vs `Wayland.cs:114`).
- **Input** (`screen/code/Window.cs:128, 231, 366–368, 481, 577, 608, 619, 649, 661–663, 678`; e.g. `:481` `onEvent("{\"clipboard\":" + JsonSerializer.Serialize(text) + "}")`; `:128` splices raw host bytes into JSON): typed items under `screen/input/`: `mouse` (kind, x, y, button, clicks, mods; wheel a kind with dx/dy), `key`, `text`, `clipboard`, `navigate`, `stats`, `video`, `closed`, and a host-message item. Consumers dispatch by a virtual `Apply`, not `ContainsKey` chains (`wayland/Display.cs:206–232`).
- **Window events** (`wayland/Window.cs:138, 357, 383–406`, `Windows.cs:35`): `window.event` variants (opened, closed, titled, focused, maximized, …), `window.click`, `window.tool`, `window.navigate`, `window.open`, `clipboard.paste`; one queue, not `Told` → Channel → Channel → `ToJsonString` → `JsonDocument.Parse` → `serializer.json.Parse`.
- **Values held as strings**: the copy value (`wayland/Address.cs:30–47`, double-encoded in `Window.cs:357`), the window address (`Address.cs:12`), a selector (`Display.cs:55–62`), key and button codes (`Display.cs:234–289`).
- **Browser frames, cursor, input, messages, screenshots** (`browser/code/Chromium.cs:277–300, 328, 348–394, 512–516`; `window/type/page.cs:144–156`; `window/screenshot.cs:27`): a `frame` item (image + size + format choice), a `cursor` choice, `input.*` items with their own DevTools form, a screenshot as an `image`, not base64 text.
- **The parent/child call protocol** (`parent/this.cs:36–84`, `terminal/code/Default.cs:373–382`, `screen/listen.cs:31–98`): the same JSON round trip in 5 places; typed `call` and `reply` items that serialize themselves (as this branch already did for Ask, `output/serializer/Reader.cs`).

## 3. Code a module already does

- **`Process.Start` ×3 in Chromium** (`Chromium.cs:74, 135, 264`, plus its own `Drain`/`PortOf`), duplicating `terminal.open`'s spawn, redirect and pumping, and missing `Children.Adopt` (a hard exit orphans Chromium on Windows). Blocker: the terminal always asks for `execute`; a system-owned launch path is a module extension (Ingi).
- **Three private `HttpClient`s** (two `static readonly`, banned; `Chromium.cs:245, 545`, `windows.cs:17`) for DevTools' `/json/version`, `/json/list`. Best fix: no HTTP at all: Chromium prints its browser websocket URL on stderr (the regex at `Chromium.cs:33` keeps only the port), and `Target.getTargets`/`setDiscoverTargets` replace `/json/list`. Else `http.request`, which needs a loopback rule (it prompts per host:port; a module extension, Ingi).
- **The terminal re-implements the stream channel** (line framing, ReadLine, text/binary write; `terminal/code/Default.cs:361–405`): a process's stdin/stdout as channel items, `OnOutput` the channel's read event, `send` a channel write.
- **Decoding images with ImageSharp in the screen provider** (`screen/code/Default.cs:99–108`): the `image` type owns ImageSharp; `Data<image>` slot.
- **Hand-rolled base64 and JSON field extraction** (`screen/code/Default.cs:72–83, 133–144`): the `base64` type, typed frame items.
- **`stats.jsonl` written from C#** inside the input pump (`screen/code/Default.cs:42–61`, via `PathHelper.Combine`): raise a typed `stats` event; a goal appends with `file`.
- **Polling** (`Chromium.cs:546–557`, `page.cs:70–83`): DevTools events (`Target.targetCreated`, `Page.loadEventFired`).

## 4. OBP shape

- **Hollow types over providers, forking on what they hold.** `screen` holds a nullable Win32 `Window` and a nullable Wayland `Display` and every member branches (`type/screen.cs:23–45`; `Open` is wrong on Linux, `Frames` always 0); `browser` holds headless and on-screen fields (`browser/type/browser.cs:53–66`, `Chromium.cs:45–46, 275, 340`); `terminal`'s `Process` is hollow while the provider holds `Send`/`Wait`/`Stop` and 19 private statics (`terminal/code/Default.cs:213–271`). Fix: abstract `screen`/`browser` with variants (window/display, headless/screen) owning their verbs, state and pumps; behaviour on `Process`; providers shrink to the native boundary (spawn, open).
- **The DevTools client written twice** (`Chromium.cs:400–522` and `window/type/page.cs:96–169`; three receive loops, two reply shapes): one `cdp` connection type with typed request/reply/event items.
- **Actions that aren't one-line doors**: six `window.*` actions copy the same 4-line preamble (`window/reload.cs:19–21`, `post.cs:24–26`, …); `window.open` calls static `Chromium.Open`, bypassing the provider; `screen/listen.cs` is an RPC server inside an action. Fix: a `data<window>` slot that resolves itself; behaviour on the types.
- **Protocol knowledge split across files**: the host frame format and QOI codec hand-written on both ends with magic kinds 1/2/3/4/5/7/9 and offsets (`wayland/Frame.cs:113–224` vs `screen/code/Window.cs:94–157, 373–411`): one `frame.message` type shared by both.
- **Lifecycle leaks**: closing a screen never disposes `Frame`/`Video` (encoder threads, pinned buffers, openh264; `wayland/Display.cs:298–305`); three `Task.Run` pumps never completed (`screen/code/Wayland.cs:46–101`); `Browser.Stop` closes no sockets or process.
- **Late stamps**: a window's `opened` event fires before its title arrives, so it always carries `title:""` (`wayland/Shell.cs:119–124`, `Windows.cs:35`): a real bug; `Browser` stamped in ~5 places after construction.
- **Statics holding state**: `Video.broken` (one decode failure disables H.264 for every display), `H264.streams` (non-atomic), `on/code/Gate.cs:13` (per-app state in a static table), the static HttpClients.
- **Cross-file locks and naked collections**: `Display.Gate` locked from three classes; public `Fds`, `Children`, `Bound`, `Windows` with four collections.
- **Names**: verb+noun and glued names (`callGoal` → `window.call`, `ActivateTop`, `OpenAnother`, `PutClipboard`, `AskCursor`, `ShowDesktop`, `DesktopWindow`, …); plural folders/types (`Windows`, `Elements`, `Popups`).
- **Bugs found on the way**: `terminal.Captured` writes all stdin before reading (deadlocks above ~64 KB with `cat`; `Default.cs:112–115`); binary mode drains stderr into an unread channel (`OnError` never fires; `:165`); `on input` and `ask` read stdin through two readers that swallow each other's lines (`on/input.cs:26` vs `channel/type/stream/this.cs:116–118`, PlangOS's main path); `terminal.wait` may deadlock against the Gate (unverified).

## 5. Core changes that bend to the branch (revert or redo as extensions)

- A screen-only `click` event hard-wired into the core event set (`event/on/click.cs`, `this.cs:27, 50, 86`): a module should declare its own events.
- Core reflection navigation changed to exact-case-first (`type/item/kind/reflection/this.cs:14–26`) to dodge a clash between the new `app.parent` and the existing `app.Parent`: rename the property, revert the reflection change.
- `goal.Enter` forks on `Elsewhere` (`goal/this.cs:76, 402`): a remote goal as its own subtype; `parent` also names the child direction (`Process.Remote`): rename (`link`/`peer`).
- The path type's `Program` lookup names the terminal and calls `File.Exists` on PATH folders before authorizing (`path/file/this.Program.cs:20–37`).

## 6. What stays (genuine boundary)

The Wayland protocol objects, wire codec, fonts, H.264 and pixel code; Media Foundation video; Landlock P/Invoke; the Windows job object; Chromium's flags. These keep their native shape; the fixes above are at their plang-facing edges.

## Module extensions that need Ingi first

1. **terminal: a system-owned program launch** (no execute prompt, adopted as a child) so `browser` can start Chromium through it.
2. **http: a loopback rule** (no per-host:port prompt for the app's own children), only if DevTools keeps HTTP (the stderr websocket URL avoids it).
3. **Module-declared events** (a module adds `click` to its own items, not the core event set).
