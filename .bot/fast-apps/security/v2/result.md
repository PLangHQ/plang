# security v2 — fast-apps full pass (decision 92), tip db28bea45

Verdict: PASS (no critical/high open). Two Medium/Low findings, one Medium package finding (with Ingi). Probes: `SubAppFullPassProbeTests` (20; 17 green, 3 red by design), `ImageSharpReachProbeTests` (1, red). Earlier containment classes re-run on the tip: see the reply.

## Findings
- **P1 (Medium, availability; with Ingi) ImageSharp 2.1.13 on untrusted bytes.** `PLang/app/type/item/image/this.cs:312` `Image.Identify(Bytes)` (ProbeDimensions) on any bytes read as an image. A 24-byte BigTIFF with a huge IFD entry count (GHSA-wmxv-xphr-5c9g, moderate) pins the reading thread: my probe's read had not ended after 10 minutes (the advisory says >5 s; the count decides). Probe `ImageSharpReachProbeTests.Identify_OnA24ByteBigTiff_AnswersQuickly` (red). Each such image read burns a thread; a program that fetches images (http) is the door. The ICC profile moderate (GHSA-gwg2-r3hj-4w44) is also in a metadata read. The three highs are NOT reached: they are HistogramEqualization, a float-TIFF decode as HalfVector4, and the TIFF CCITT T4/T6 encoders; the code does none of these (it decodes Bgra32 at `screen/window/this.cs:154`, saves PNG only at `screen/view/this.cs:70`). `DetectFormat` (`image/this.cs:287`) reads magic bytes only. Fix: ImageSharp 4.1.2 (split licence), or refuse TIFF before Identify and read png/jpeg/gif/webp headers by hand; either way Ingi's call.
- **D4-1 (Low, latent) identity.export in a sub app hands the MAKER's private key on the sub's actor's yes.** `actor/this.cs` `origin.Identity` (decision 4) gives the sub's System/User the maker actor's identity object; `module/identity/code/Default.cs:306` returns it as the default, and `export` asks only the sub's own input channel. Probe `D4_ExportInTheSub_WithTheSubsYes_DoesNotHandTheMakersKey` (red). Reach: only the test runner makes sub apps and its test is the maker's own program under the developer's channel; the maker's User can already export the app default with its own yes. Becomes real when a request app makes sub apps for a visitor's actor. Fix (architect's call): export refuses an identity the app was not made holding (the origin's), or asks the maker's actor.
- **T1 (Low, latent) a sub app's store location is decided at its first touch by the current Mode.** `app/this.cs:358-365` (`Mode.Value == Test` read when the lazy store opens). A sub of a NON-testing maker, touched before its session opens or after it closes, opens the maker's `.data/data.sqlite` on disk (same folder). Probes `T_LATENT_*` (2, red). The runner's order (born, session opened, run, disposed) is green (`T_TheRunnersOrder_LeavesTheMakersDiskAlone`), and a sub of a testing maker stays in memory down a chain, even after its session closes (green). Fix: a sub app made to test is testing from birth (origin knows, as for a testing maker), not by session.
