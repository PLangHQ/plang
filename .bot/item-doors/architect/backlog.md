## Brainstormed with Ingi, not designed (decision 318)

1. **Diff: a save writes only what changed** (new, Ingi: "that needs to be added, but not into this branch, this is something new"). The diff is between two values, the new content and the file; it answers a `patch` (NEW type): pieces, each `start` (a byte position in the file as it is now) and `bytes` (as the file's own format writes them, so positions, encoding and line endings agree with a whole save), and `length` (the file's length after). A piece that changes length carries the rest of the file with it; no change answers no pieces; no file answers one piece at 0. Save's handler stays as it is; the step's code chains the two (`text.diff(…); file.save(Value=%!data%)`). Open: the patch's own write into a file (each piece at its start, then the length), since today the file channel writes a value from the start through the extension's format (`path/file/this.Operations.cs:183`). Why not a `Diff` property that rewrites the action's `Text`: the dependency on order is invisible, a resolve before Start makes the rewrite too late, and actions are shared across runs (`goal/step/action/this.cs:186`).
2. **An option that changes a value is its own action in the step** (brainstorm). `file.read`'s `Template` (`module/file/read.cs:30–44`, three paths in one handler) would be `file.read(…); template.fill(Value=%!data%)`, so a fill works on any value (a file, an http answer, an llm answer). The same for diff, compress, encrypt. An option that's only the action's own setting (`Overwrite`) stays an option. Cost: the builder chains two actions where it set one option.
3. **Required carriers resolved before Start; handlers as a block, one line after another** (brainstorm; Ingi: "it should be { .... } not this => stuff", "ofc it's await"). The generated `Resolve` (already before Start, its error recorded on the frame: `goal/step/action/this.cs:325–330`) resolves each required carrier and answers the first that fails. Optional carriers stay lazy. An exit (an ask that suspends) is answered as the carrier whole, but `Resolve` returns only `Error?` (`module/ICodeGenerated.cs:29`). Save's handler becomes `{ var path = await Path.Value(); return await path.Save(Value, Context); }`, with no `Use` and no `From`. `.Use` stays its name, not `.Start` (`Task.Start(task => task.Cancel())` reads as starting the task). `data` is locked: Ingi's yes, and a re-pin.
4. **Each actor's store, and an app made for each request** (317a, tabled). The webserver is a terminal app whose User starts the server; each request is an app whose System is that User and whose User is the caller (identity optional, never a private key on the server). Keys stay inside the app (backups: every app the same sqlite; sub apps each with their own key); no outside key store. The architect's open proposal: a store belongs to an actor, and stores nest as actors do (`/.data/`, `/.data/user/`, `/.data/user/<caller>/`), so a System's standing grant names its maker's store.
