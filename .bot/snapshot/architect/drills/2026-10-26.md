# OBP drills, 2026-10-26

Real code from the tree, read as it stands. For each piece: the situation it's in, the pattern it should follow (numbered as in `Documentation/v0.2/obp-patterns.md`), the tell it shows, how I'd rewrite it, and why. Nothing here is built; a rewrite that touches the locked core is a proposal.

## Drill 1: `module/loop/foreach.cs`, the loop's state

```csharp
public async Task<data.@this> Start()
{
    …
    var answered = Parallel != null && await Parallel.ToBooleanAsync() && await Parallel.Value() is { } side && Step?.Goal is { } goal
        ? Context.Ok(Started(goal, side, itemVariable, keyVariable, body))
        : await Run(itemVariable, keyVariable, body);
    …
}
private async Task<data.@this> Run(…)
{
    int count = 0;                                              // :74
    await foreach (var (names, failed) in Bound(itemVariable, keyVariable))   // the position: the iterator's
    {
        …
        await using (Context.call.Push(names, setting))
            foreach (var action in body) { … }                  // which body action: a local
        count++;
    }
    return await Result(count, complete: true);
}
private async Task<data.@this> Result(int count, bool complete)
    => await Context.App.type.list["dict"].Create(
        new Dictionary<string, object?> { ["count"] = (long)count, ["complete"] = complete }, Context);
```

**Situation:** a loop runs over a collection. Its running state (the collection as read, where it is, how many have run) must survive a save (Ingi's 67), and it answers a result.

**Matches, three tells:**
- *Pattern 1, saved data:* the loop's state lives in C# locals (`count`, the iterator, the body's index), so nothing can write it. It's state with no object to write it.
- *Pattern 1 again, someone packing by key:* the answer is a dict built by hand (`["count"]`, `["complete"]`), so the result's shape is rewritten wherever it's read.
- *Pattern 2, one operation and two behaviours chosen by a flag:* `Parallel != null && … ? Started(…) : Run(…)` is two execution paths for one loop (the fork smell).

**Rewrite:**
```csharp
// module/loop/type/loop/this.cs — NEW: a running loop, a value that writes itself
public abstract class @this : item.@this
{
    [Snapshot] public data.@this Collection { get; }          // read once, at the loop's step, as it was
    [Snapshot] public number Position { get; private set; }   // the next element to run
    [Out, Snapshot] public number Count { get; private set; }
    [Out] public @bool Complete { get; private set; }
    internal abstract Task<data.@this> Run(IReadOnlyList<action.@this> body, actor.context.@this context);
}
// loop.sequence: one element after another, from Position; it moves Position as each one ends
// loop.parallel: each element a task, at most its cpu at once
```
`foreach.Start` makes the kind the step asked for, once (pattern 2: at birth, by the one who knows: the step's own `Parallel` parameter). It holds the loop on its frame, and answers the loop itself: `{count, complete}` is the loop's `[Out]` face, not a dict built by hand. On resume the frame's loop comes back by its `[Snapshot]` members, and `Run` goes on from `Position`. That's question 3's answer for loops, by pattern, not by a special mechanism.

**Why:** state that must be saved needs an object that owns it. A local can't be written, and a hand-built dict is an envelope. Choosing the kind once removes the fork.

## Drill 2: `goal/this.cs:149–169`, what kind of goal it is

```csharp
public bool IsSetup => Name.Equals("Setup", …) || Under("setup");
public bool IsSystem => Under("system");
public bool IsTest => Where.EndsWith(".test.goal", StringComparison.OrdinalIgnoreCase);
private ReadOnlySpan<char> Where => (Path?.Raw ?? "").AsSpan().TrimStart("/\\");
private bool Under(string folder)
    => Where.StartsWith(folder, …) && Where.Length > folder.Length && Where[folder.Length] is '/' or '\\';
```

**Situation:** deciding what a goal is (setup, system, test) from where its file sits.

**Matches:** *pattern 8, the value answers.* The goal cracks its path into a character span (`Path.Raw`, `TrimStart`, `StartsWith`, `EndsWith`) and parses it by hand. That's the opened box and raw hand-off smells: the path owns its location, and here the goal does the path's job.

**Rewrite:**
```csharp
public bool IsSystem => Path is { } path && path.Under(App.filesystem.system);   // the path answers where it sits
public bool IsTest => Path is { } path && path.Name.Is(test.Name);                 // the file's name answers its kind
```
`path.Under(folder)` belongs on `path` (NEW if it doesn't exist: check `path/this.Derivation.cs` first). A goal with no path is still a `Path is {}` check here. If composed goals multiply, they're a kind of their own (pattern 2); today the one check is honest.

**Why:** two owners shouldn't both know how a location is spelled. When the path changes how it's written (Windows separators are already handled twice here: `'/' or '\\'`), only the path should change.

## Drill 3: `goal/this.cs:208–221`, a goal's address

```csharp
public string? Address
{
    get
    {
        if (Parent is { } parent) return parent.Address is { } above ? $"{above}#{Name}" : null;
        var path = Path?.ToString();
        if (string.IsNullOrEmpty(path)) return null;
        return path.EndsWith(".goal", …) ? path[..^5] : path;
    }
}
```

**Situation:** naming a goal so it can be found again.

**Matches:** *pattern 6, a compound name,* and *pattern 4, whoever names it finds it.* The address glues two things, the file (its path minus `.goal`) and the name inside it (`#Name`), into one string, which `goal.list` then parses apart again to find the goal. `ToString` and `[..^5]` are the tells.

**Rewrite:** inside C#, a goal is found by what it is made of, `{pr, name}` (decision 86's shape), and `goal.Select` takes that. The address string stays only where plang text writes it (a step's `call /start#show`), parsed once at that perimeter into the same `{pr, name}`.

**Why:** a string that must be parsed back apart is a record pretending to be a name. The snapshot already moved to `{pr {path}, name}`; the same reasoning applies inside the runtime.

## Drill 4: `type/item/this.cs:220–228`, the `on` door

```csharp
public virtual async ValueTask<data.@this> Get(data.@this parent, string key)
    => await Member(parent, key) ?? On(parent, key) ?? await Setting(parent, key)
       ?? (this as property.IOwner)?.property[key] ?? parent.Context.NotFound(key);

// This value's events when the key is `on` — the event door, read by name though no member lists it.
private data.@this? On(data.@this parent, string key)
    => string.Equals(key, "on", StringComparison.OrdinalIgnoreCase) ? … : null;
```

**Situation:** navigating to a member by name.

**Matches:** *"is this X?" by string* (the shape smell, and pattern 7, one door). `on` is a member in every sense except that it isn't listed, so `Get` has a second door that matches its name by hand. The type node does the same for `list` (`type/node/this.cs:103`), and I accepted stage 8 copying that precedent into `property.list`. The drill shows the precedent itself has the tell.

**Rewrite:** `on` becomes a listed member, and `Member(parent, key)` finds it through the one door.

**Check first:** why `on` isn't listed. If it was kept out of the builder's catalog so every type doesn't advertise `on`, the real question is whether the catalog's listing and the member lookup should be one list or two. That's a question to answer before rewriting, not a rule to apply blindly.

**Why:** two doors for "a member by name" means the next special name gets a third.

## Live miss: a goal's `.pr` (snapshot 88)

I ruled that a goal's makers set `Pr` beside `Path` (pattern 5, a birth fact). The coder's count showed the cost: 69 hand-built test goals, each needing both, or the goal list refuses them. **The tell I missed:** `Pr` is *derived* from `Path`. A derived fact set separately is the same fact stored twice, and every maker has to remember both. **Rule:** pattern 5 is for a fact only the maker knows (a step's list). A fact that follows from another one is computed from it, by the owner, with what the owner already reaches: here the type list the goal's own type is in. **The signal to watch:** when a rule makes every construction site do one more thing, check whether that thing is derived.

## What the drills taught me

- Precedent isn't proof. Drill 4's tell was in code I'd approved as "the existing pattern".
- Question 3 (loops) isn't a special mechanism: it's pattern 1 applied to state that lives in locals.
- The strongest tell is a string being cut apart or glued together (drills 2 and 3). A value is being treated as text.
